# Maintained tools and owner-specific runners

The current EDP-Serial repository has **no maintained Python generator, schema registry, offline decoder or code-generation runtime**. Its maintained non-C++ tooling is the explicit Bash host test runner set: `tests/run_host_tests.sh` compiles and executes `tests/ByteEndpointTests.cpp` against actual EDP-System Composition; `tests/run_logging_frame_host_tests.sh` compiles real EDP-Logging frame writer/reader with `tests/EdlgFramePumpTests.cpp`; `tests/run-bounded-edlg-queue-tests.sh` compiles the Threading-keyed FIFO with `tests/BoundedEdlgFrameQueueTests.cpp`. Each is fail-fast `set -euo pipefail`, takes `CXX` and documented explicit source-root environment variables, creates a temporary executable and cleans it with an EXIT trap. None flashes an MCU, installs a native UART driver, or proves device wire output. Host compiler results are not power-loss certification.

The three PIO demonstration project manifests choose Arduino-ESP32 vs ESP-IDF and source-relative sibling libraries. Their `src/main.cpp` and Arduino IDE sketches are **examples**, not duplicated library implementations. Exact build targets/receipts should be pinned in [Build/Test/Source](Build-Test-and-Source) and the [central Policy handoff](https://github.com/ESPressio-Development-Platform/Policy/blob/main/Handoff/2026-11-09/2026-11-09-09-29-EDP-Logging-Dependency-First-Reintegration.MD).
